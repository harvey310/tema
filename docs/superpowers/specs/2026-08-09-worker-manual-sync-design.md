# Tema 手动抓取与共享数据设计

## 1. 目标

把当前依赖内置 CSV 和浏览器 `localStorage` 的静态页面，改造成由 Cloudflare Worker 提供页面和接口、由 D1 保存共享开奖记录的动态应用。

管理员输入密码后可以手动抓取最新开奖记录。抓取数据经过完整校验并成功写入 D1 后，所有设备重新读取页面都能看到相同结果。

## 2. 本次范围

### 包含

- Cloudflare Worker 后端与静态资源托管。
- D1 数据库结构和现有 2026 年开奖记录初始化。
- 管理员密码登录、会话检查和退出。
- 管理员手动触发开奖记录抓取与同步。
- 公共读取开奖记录、最新期号和最近同步状态。
- 页面“更新数据”按钮、密码弹窗和更新结果提示。
- 现有“新增一期”改为管理员操作，并写入 D1。
- 删除原来的“恢复初始数据”入口，防止共享数据被整体覆盖。
- 自动化测试、部署配置和操作说明。

### 不包含

- 多管理员账号体系、找回密码和角色管理。
- 自动定时抓取。
- 修改 GitHub 中的内置 CSV 或由 Worker 自动提交 GitHub。
- 2025 年及其他年份的数据管理。

## 3. 推荐架构

Cloudflare Worker 同时处理动态接口和静态页面，避免跨域配置和前端直接访问数据源。

```text
浏览器
  ├─ GET /                       → Worker Static Assets → 页面
  ├─ GET /api/records            → Worker → D1 → 共享开奖记录
  ├─ POST /api/admin/login       → Worker → 校验 Secret → 安全 Cookie
  ├─ POST /api/admin/sync        → Worker → 抓取源站 → 校验 → D1
  └─ POST /api/admin/records     → Worker → 校验 → D1
```

GitHub 只保存代码、配置和数据库迁移文件。开奖记录的线上正式数据保存在 D1，不再通过修改 `index.html` 发布。

## 4. 文件职责

- `public/index.html`：现有看板页面，改为从 API 加载数据并提供管理员更新入口。
- `src/index.js`：Worker 路由入口、静态资源转发和统一错误响应。
- `src/auth.js`：管理员密码校验、签名会话 Cookie、登录状态和来源校验。
- `src/records.js`：D1 查询、单条新增和批量写入。
- `src/sync.js`：抓取源选择、解析、数据校验和同步结果生成。
- `migrations/0001_initial.sql`：开奖记录和同步日志表结构。
- `migrations/0002_seed_2026.sql`：把当前已确认的 2026 年开奖记录写入 D1。
- `test/`：认证、解析、同步、接口和数据校验测试。
- `wrangler.jsonc`：Worker、静态资源和 D1 绑定配置。
- `package.json`：本地开发、测试、迁移和部署命令。

## 5. 数据结构

### `draw_records` 开奖记录表

| 字段 | 类型 | 规则 |
|---|---|---|
| `year` | INTEGER | 固定为 2026 |
| `period` | INTEGER | 期号，2026 年内唯一 |
| `draw_date` | TEXT | `YYYY-MM-DD` |
| `normal_1` 至 `normal_6` | TEXT | 保存号码、生肖和波色的标准字符串 |
| `special` | TEXT | 保存特码号码、生肖和波色的标准字符串 |
| `source_url` | TEXT | 本条记录最后采用的数据来源 |
| `created_at` | TEXT | 首次写入时间 |
| `updated_at` | TEXT | 最后更新或核验时间 |

主键使用 `(year, period)`。同一期再次抓取时，如果日期或号码不同，拒绝自动覆盖并记录同步失败，避免错误源悄悄改写历史数据。

### `sync_runs` 同步日志表

记录开始时间、结束时间、数据来源、抓取条数、新增条数、最新期号、执行结果和错误信息。页面只公开最近一次成功同步的摘要，详细错误只在管理员操作结果和 Cloudflare 日志中显示。

### `admin_login_attempts` 登录失败记录表

只保存客户端 IP 的 `SESSION_SECRET` 哈希、失败时间和自动过期时间，不保存明文 IP 或密码。用于限制同一来源 10 分钟内最多失败 5 次；过期记录在后续登录请求中清理。

## 6. 抓取与校验规则

1. 服务端先访问用户指定源 `https://2025kj.zkclhb.com:2025/am.html`。
2. 指定源连接失败、返回非 2xx 或解析不到有效数据时，再访问已验证历史源 `https://history.macaumarksix.com/history/macaujc2/y/2026`。
3. 只接受开奖日期属于 2026 年的记录。
4. 每条记录必须包含期号、日期、平一至平六和特码，共七个号码。
5. 每个号码必须在 01–49 范围内，且同一期七个号码不得重复。
6. 期号不得重复；抓取结果按期号去重后必须连续。若源站返回重复副本，内容完全一致时合并，内容冲突时整次同步失败。
7. 所有记录通过校验后才开始数据库写入。
8. 写入时只新增不存在的期号；历史同一期内容不一致时整次同步失败，不部分写入。
9. 同步成功返回抓取条数、新增条数、最新期号、开奖日期、实际来源和完成时间。

## 7. 接口设计

### 公共接口

- `GET /api/records?year=2026`
  - 返回全部 2026 年开奖记录、总数和最新一期。
- `GET /api/status`
  - 返回服务是否可用、最新成功同步摘要和当前数据总数。

### 管理员接口

- `POST /api/admin/login`
  - 请求：`{ "password": "..." }`
  - 成功后设置 30 分钟有效的 `HttpOnly; Secure; SameSite=Strict` 签名 Cookie。
- `GET /api/admin/session`
  - 返回当前管理员会话是否有效。
- `POST /api/admin/logout`
  - 清除管理员 Cookie。
- `POST /api/admin/sync`
  - 仅管理员可用，执行一次完整抓取、校验和写入。
- `POST /api/admin/records`
  - 仅管理员可用，新增一期人工记录；不得覆盖已有期号。

所有写接口只接受同源请求，并检查 `Origin`、请求方法、JSON 类型和管理员会话。接口错误使用明确的状态码和中文错误信息，不静默吞错。

## 8. 管理员安全设计

- 管理员密码通过 Cloudflare Secret `ADMIN_PASSWORD` 配置，不进入 GitHub、HTML、日志或数据库。
- 会话签名密钥通过 Cloudflare Secret `SESSION_SECRET` 配置。
- 登录时采用恒定时间比较，避免简单时序泄漏。
- 登录失败只返回“密码错误”，不返回内部配置细节。
- 登录接口使用 D1 登录失败记录限制同一来源 10 分钟内最多失败 5 次，超限返回 429。
- 同步接口发现两分钟内已有未结束任务时返回 409，防止重复点击造成并发抓取和写入。
- 会话 Cookie 只用于同域 Worker，前端 JavaScript 无法读取。
- 未配置 Secret 时管理员接口直接报配置错误，不能以默认密码运行。

## 9. 页面交互

### 首次加载

- 页面显示“正在加载共享数据”。
- `GET /api/records` 成功后渲染看板，并显示数据总数、最新期号和最近同步时间。
- 接口失败时显示明确错误，不能用旧 `localStorage` 假装数据正常。

### 手动更新

- 页头增加“更新数据”按钮。
- 未登录时点击按钮，打开管理员密码弹窗。
- 登录成功后立即执行同步；已登录时直接执行同步。
- 更新期间按钮禁用并显示“正在抓取”。
- 成功后刷新共享数据，并显示新增条数、最新期号、开奖日期和实际来源。
- 无新增记录时显示“数据已是最新”，仍记录本次成功同步。
- 失败时保留数据库原数据，显示服务端返回的可理解错误。

### 手工新增

- “新增一期”入口仅在管理员会话有效时显示。
- 保存前校验期号、日期和七个号码。
- 已存在的期号不允许覆盖，避免人工误改历史开奖。

## 10. 部署和配置

- Worker 项目名：`tema`。
- Cloudflare Git 构建命令：留空。
- Cloudflare Git 部署命令：`npx wrangler deploy`。
- D1 数据库建议名称：`tema-db`，Worker 绑定名称固定为 `DB`。
- 静态资源目录：`public`，绑定名称为 `ASSETS`。
- 必需 Secrets：`ADMIN_PASSWORD`、`SESSION_SECRET`。
- 首次上线前必须应用全部远端 D1 migration，再部署 Worker。

## 11. 验收标准

- 未登录用户能正常读取共享开奖记录，但不能调用同步或新增接口。
- 密码错误无法建立管理员会话；密码不出现在仓库和浏览器存储中。
- 管理员点击更新后，服务端能使用可用来源抓取并写入 D1。
- 抓取到重复副本时能正确去重；冲突、缺字段、号码越界或非 2026 数据不会写入。
- 两个不同浏览器在更新后读取到相同记录数和最新一期。
- 数据源失败或 D1 写入失败时，原有数据保持不变，并能查到失败日志。
- 页面不再依赖 `localStorage` 保存正式开奖记录。
- 单元与接口测试全部通过，本地 Worker 能加载页面和 API。

## 12. 主要代价与边界

- 从静态页面升级为动态服务后，部署前必须正确创建 D1、应用迁移并配置两个 Secret。
- Cloudflare 免费额度足以覆盖当前低频手动更新和少量访问；实际额度和计费以 Cloudflare 当前账户页面为准。
- 源站结构变化会导致同步明确失败，需要更新服务端解析器，不采用模糊猜测或错误数据兜底。
